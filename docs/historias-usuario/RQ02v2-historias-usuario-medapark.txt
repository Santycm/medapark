2. Contexto del sistema 
2.1. Descripción del proyecto 
Diseño y construcción de una aplicación web que permite la gestión y consulta de 
 parqueaderos en la ciudad de Medellín. La plataforma tiene dos tipos de actor: 
• Usuario (sin cuenta): consulta de forma pública y anónima la ubicación, horarios, 
tarifas y disponibilidad de celdas para automóviles y motocicletas de los parqueaderos 
registrados, y genera una ruta hacia el que seleccione mediante Google Maps. 
• Administrador de Parqueadero (con cuenta, creada manualmente por el equipo de 
 desarrollo): gestiona la información de su propio parqueadero — datos generales, 
tarifas, celdas disponibles por tipo de vehículo — y actualiza el estado de ocupación de 
las celdas conforme ingresan y salen vehículos. 
La plataforma se construye con React (frontend, desplegado en Netlify) y Supabase 
(backend: autenticación, base de datos PostgreSQL y API).

HU1 Nombre de la historia  Iniciar sesión 
 
Como Administrador de Parqueadero necesito iniciar sesión con mi usuario y contraseña, para 
acceder a las funcionalidades de gestión de mi parqueadero. 
 
Campos 
 
❖ Correo electrónico (obligatorio). 
❖ Contraseña (obligatorio). 
❖ Botón “Ingresar”. 
 
Criterio de aceptación 
 
❖ El campo Correo electrónico debe validar que el dato ingresado tenga el formato de correo 
electrónico (usuario@dominio); si no cumple el formato, se muestra "Verificar correo 
electrónico". 
❖ Si alguno de los campos obligatorios está vacío, el sistema no debe permitir el inicio de sesión 
y debe indicar que se deben completar los campos requeridos. 
❖ Si el correo y/o la contraseña no coinciden con una cuenta registrada, se muestra el mensaje 
"El correo electrónico o la contraseña son incorrectos". 
❖ Si el inicio de sesión es exitoso, el Administrador es redirigido al panel de gestión de su 
parqueadero. 
❖ El botón "Ingresar" debe estar conectado a Supabase Auth para su validación de ingreso. 
❖ No existe formulario de registro público: las cuentas de Administrador de Parqueadero son 
creadas directamente por el equipo de desarrollo desde Supabase; por lo tanto, esta pantalla 
no tiene opción de "Registrarse". 
❖ Se implementa autenticación multifactor (MFA). 
❖ El rol Usuario no tiene ni necesita pantalla de inicio de sesión — accede directamente a la 
plataforma sin autenticarse (ver HU9). 
 
Aclaración: esta es la única pantalla de autenticación de todo el sistema; no hay pantallas de registro, 
recuperación ni cambio de contraseña en el MVP.

Como Administrador de Parqueadero necesito verificar mi identidad mediante un 
segundo factor de autenticación después de ingresar correctamente mi correo 
electrónico y contraseña, para aumentar la seguridad de acceso al panel de 
administración. 
 
Campos 
❖ Código de verificación MFA (obligatorio). 
❖ Botón "Verificar código". 
❖ Botón/enlace "Reenviar código". 
❖ Opción "Volver al inicio de sesión".

Criterio de aceptación  
❖ El MFA aplica únicamente a las cuentas de Administrador de Parqueadero. 
❖ El Administrador debe haber ingresado correctamente su correo electrónico y 
contraseña en la HU1 antes de acceder a la verificación MFA. 
❖ Si el correo o la contraseña son incorrectos, el sistema no debe mostrar la pantalla 
MFA. 
❖ Después de validar correctamente las credenciales, el sistema debe generar/enviar un 
código de verificación mediante el mecanismo MFA configurado. 
❖ El sistema debe mostrar un campo obligatorio para ingresar el código de verificación. 
❖ El código debe tener una vigencia limitada. Una vez vencido, no puede utilizarse. 
❖ El sistema debe comprobar que el código ingresado corresponda al generado para esa 
autenticación y continúe vigente al seleccionar "Verificar código". 
❖ El sistema completa la autenticación y redirige al Administrador al panel de gestión de 
su parqueadero (HU3) si el código es correcto.  
❖ Si el código es incorrecto, debe mostrarse el mensaje "El código de verificación es 
incorrecto" y no se debe permitir el acceso al panel. 
❖ Si el código ha vencido, debe mostrarse "El código de verificación ha expirado. 
Solicita uno nuevo". 
❖ La opción "Reenviar código" debe generar un nuevo código de verificación e 
invalidar el anterior. 
❖ El sistema debe limitar los intentos consecutivos de verificación para evitar ataques de 
fuerza bruta. 
❖ El Administrador no debe poder acceder directamente mediante URL a las 
funcionalidades administrativas mientras la verificación MFA esté pendiente. 
❖ Al seleccionar "Volver al inicio de sesión", debe cancelarse el proceso de 
autenticación pendiente y regresar a HU1. 
❖ La sesión del Administrador solo debe considerarse completamente autenticada 
después de superar correctamente ambos factores. 
❖ El MFA no debe modificar la información del parqueadero, tarifas, capacidad de celdas 
ni datos de ocupación existentes. 
 
Aclaración: esta historia amplía la autenticación definida en HU1.

Configurar celdas del parqueadero 
 
Como Administrador de Parqueadero necesito registrar la cantidad de celdas disponibles para 
automóviles y motocicletas, para que el sistema pueda calcular y mostrar la disponibilidad a los 
usuarios. 
 
Campos 
 
❖ Cantidad total de celdas para automóviles (numérico; obligatorio si el parqueadero atiende 
automóviles, ver HU3). 
❖ Cantidad total de celdas para motocicletas (numérico; obligatorio si el parqueadero atiende 
motocicletas). 

=====PAGE 15 images: 0

Criterio de aceptación  
❖ Solo se solicitan los campos de los tipos de vehículo que el parqueadero atiende (definidos en 
HU3); si el parqueadero no atiende motocicletas, no se muestra el campo de celdas de moto. 
❖ Los valores deben ser números enteros mayores a cero. 
❖ Se puede actualizar el número de celdas a 0, solo si no hay celdas ocupadas. De lo contrario, 
primero se deben registrar las salidas hasta quedar con todas las disponibilidades de celdas. 
❖ Al guardar por primera vez, el sistema inicializa esa cantidad de celdas en estado Disponible. 
❖ El administrador puede modificar la cantidad total en cualquier momento (aumentar o disminuir).  
❖ Si intenta reducir la cantidad total por debajo de las celdas actualmente marcadas como ocupadas 
(ver HU7), se muestra el mensaje de advertencia: "No puede reducir la cantidad de celdas por 
debajo de las celdas actualmente ocupadas" y no se guarda el cambio. 
❖ Esta pantalla gestiona la cantidad total configurada de celdas por tipo, no el estado individual de 
ocupación de cada una — eso se gestiona en HU7 y HU8. 
 
Aclaración: la plataforma no distingue celdas individuales con numeración o identificador propio visible al 
Usuario; se gestiona como un conteo agregado de disponibles/ocupadas por tipo de vehículo (no hay 
mapa de celdas físicas dentro del parqueadero). Estas opciones las configuramos en la HU3 y las 
podemos editar en la HU5.

❖ Al seleccionar "Registrar salida", el sistema debe disminuir en uno la cantidad de celdas 
ocupadas del tipo de vehículo correspondiente. 
❖ Al registrar una salida, la cantidad de celdas disponibles debe aumentar en uno. 
❖ El sistema no debe permitir registrar una salida cuando la cantidad de celdas ocupadas del tipo

❖ La cantidad de celdas ocupadas debe ser inferior a cero. 
❖ Después de registrar un ingreso o una salida, el sistema debe actualizar inmediatamente el 
conteo mostrado al Administrador. 
❖ La nueva disponibilidad debe almacenarse para que pueda ser consultada posteriormente por los 
usuarios. 
❖ Los usuarios visualizarán el último estado de disponibilidad registrado cuando consulten o 
recarguen la plataforma. 
❖ MEDAPARK no realizará actualización automática en tiempo real de la información que ya se 
encuentre abierta en el dispositivo de otro Usuario. 
❖ La disponibilidad actualizada debe reflejarse en el panel de gestión del Administrador (HU3) y en 
el detalle público del parqueadero (HU10).

4. Glosario de términos 
HU, Historia de usuario: requisito funcional redactado desde la perspectiva de quien lo necesita, 
con sus criterios de aceptación. 
MVP, Producto Mínimo Viable: primera versión de la plataforma con el alcance mínimo necesario 
para entregar valor real, descrito en la propuesta comercial firmada. 
Parqueadero, Establecimiento registrado en la plataforma que ofrece celdas de estacionamiento 
para automóviles y/o motocicletas. 
Celda, Espacio de estacionamiento dentro de un parqueadero; se gestiona como conteo agregado 
(disponible/ocupada) por tipo de vehículo, sin identificador individual visible al Usuario. 
Administrador de Parqueadero, Rol con cuenta (creada manualmente por el equipo de desarrollo) 
que gestiona la información, tarifas, celdas y disponibilidad de su único parqueadero. 
Usuario, Rol sin cuenta que consulta parqueaderos, disponibilidad y tarifas de forma pública y 
anónima, y genera rutas hacia el parqueadero seleccionado. 
RLS (Row Level Security), Mecanismo de seguridad de Supabase/PostgreSQL que restringe qué 
filas de una tabla puede leer o modificar cada usuario, usado para separar el acceso público 
(Usuario) del acceso autenticado (Administrador). 
Disponibilidad, Conteo de celdas libres por tipo de vehículo en un parqueadero, actualizado 
manualmente por el Administrador de Parqueadero. 
 
5. Riesgos preliminares 
• Concentración de conocimiento técnico: el rol de Desarrollador es rotativo entre los 3 
integrantes del equipo (según la propuesta comercial), lo que puede generar curva de 
aprendizaje o inconsistencias de estilo/código entre módulos si no se documenta bien 
cada entrega. 
• Dependencia de información externa: el listado inicial de parqueaderos (con ubicación, 
horarios y tarifas vigentes) debe ser entregado por la Alcaldía de Medellín; un retraso en 
esta entrega puede bloquear las pruebas de datos reales antes de la entrega final. 
• Ausencia de recuperación de contraseña: si un Administrador de Parqueadero olvida su 
contraseña, depende completamente de que el equipo de desarrollo se la restablezca 
manualmente — riesgo operativo si el equipo no está disponible en el momento en que se 
necesita. 
• Calidad de la disponibilidad depende 100% de la disciplina operativa del Administrador: si 
el administrador olvida registrar un ingreso o salida, la disponibilidad mostrada a los
